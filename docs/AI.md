# Участник №1, шаг 2: AI-конструктор

Реализованы две операции: анализ описания с уточняющими вопросами и извлечение
карточки из пользовательского текста/ответов. OpenAI — единственный внешний провайдер.
В режиме `local` работает явно обозначенная локальная заглушка, разрешённая кейсом.

## Настройка

В Git хранится только `.env.example`. Скопируйте его в `.env`, если своего файла ещё нет.

```dotenv
AI_MODE=local
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
AI_TIMEOUT_SECONDS=20
```

Для внешней модели заполните ключ в `.env`, установите `AI_MODE=openai` и
перезапустите сервер. Модель настраивается; она должна поддерживать Responses API
и Structured Outputs. Клиент не получает ключ. Вызовы идут только на
`https://api.openai.com/v1/responses`, с `store=false`, без инструментов и внешнего поиска.
Таймаут — 1–60 секунд, по умолчанию 20. Автоматических повторов и скрытого перехода
на другой режим нет. Таймаут HTTPX ограничивает сетевые операции, а не гарантирует
общую длительность запроса при медленной потоковой передаче.

`GET /api/ai/status` сообщает режим по умолчанию и наличие ключа, но не проверяет
баланс или доступность модели. Выбор `mode=local` в запросе работает и при серверном
режиме openai, не отправляя данные провайдеру.

## Быстрый прогон через /docs

1. `POST /api/tasks`, заголовок `X-Demo-Business-Id: business-1`:
   `{"original_text":"У нас постоянно путаются остатки товаров.","topic":"retail"}`.
2. `POST /api/tasks/{id}/questions`, тело `{"mode":"local"}` или `{"mode":"openai"}`.
3. Возьмите ID вопросов из ответа и вызовите `POST /api/tasks/{id}/generate-card`,
   например `{"mode":"local","answers":{"q-data":"Есть тестовый CSV на 500 товаров."}}`.
4. Получите редактируемую `task.proposed_card`. `task.confirmed_card` и
   `task.published_card` остаются прежними. На новой задаче они равны `null`.
5. Ручные правки сохраняются обычным PATCH задачи. Подтверждение и рейтинг — шаг 3.

Запросы для UI и JSON-примеры: [API.md](API.md), [ai-examples.json](ai-examples.json).
Участник №2 подключает эти операции к конструктору. HTML/CSS и навигация на шаге 2
участником №1 не изменялись; статические вопросы в существующем UI пока не вызывают AI.

## Промпт и формат модели

Точные промпты: `SYSTEM_PROMPT`, `QUESTIONS_PROMPT`, `CARD_PROMPT` в `app/ai.py`.
Их можно показать жюри вместе с JSON-схемой, передаваемой через `text.format`.

Вход модели — JSON с `draft_text`, `topic`, `current_card` и массивом ответов
`[{id, field, question, answer}]`. Ключ, профиль бизнеса, закрытые снимки и исходный
текст до пользовательских исправлений в модель не передаются.
Ранее сгенерированная карточка не используется как новое доказательство после
изменения исходных данных; ручное редактирование делает её пользовательским текстом.

Выход вопросов: `{"questions":[{"field":"data","text":"Какие данные доступны?"}, ...]}`.
Проверяются 3–7 вопросов, непустые строки, разрешённые поля, разные тексты и поля.
Сервер назначает стабильные ID `q-{field}`. При повторной генерации сохраняются
вопросы, на которые уже ответили, поэтому итоговый сохранённый список может быть длиннее.

Выход карточки: `{"card":{...все поля TaskCard...}}`. Модель обязана вернуть все
поля и не может добавить статус, рейтинг или другие ключи. Неизвестные сведения —
пустые строки. Значения бизнес-полей должны быть дословными фрагментами входных
данных; неподтверждённая цитата отклоняется. Прямой ответ на поле имеет приоритет.
Фразы вроде «не знаю» остаются в ответах, но соответствующее поле карточки пусто.

Это консервативное извлечение, а не свободное переписывание: модель не может
добавить новый срок, контакт или число. Проверка наличия цитаты не доказывает
смысловую правильность её отнесения к полю, поэтому ручная проверка остаётся обязательной.
Необязательные AI-советы хранятся отдельно в `ai_recommendations` и не становятся
требованиями бизнеса или основанием для баллов.

## Локальная заглушка

Без внешней модели выбираются 3–5 шаблонных вопросов по незаполненным полям,
с цитатой из конкретного описания. Карточка собирается копированием явно введённых
ответов и предложений, обнаруженных по ключевым словам. Числа и контакты не
придумываются. Выделение по ключевым словам может ошибиться с назначением поля;
пользователь может исправить результат. Этот режим не заявляется как LLM.

В ответе и в БД сохраняются `mode`, `model`, пояснение и время генерации. UI должен
показывать это пояснение. При отказе OpenAI сервер возвращает понятную ошибку и
предлагает явно повторить запрос с `mode=local`, не подменяя ответ незаметно.

## Сохранность и проверки

Валидные ответы сохраняются до вызова провайдера. Некорректный JSON, отказ модели,
таймаут или неподтверждённые факты не затирают старые вопросы/карточку. Изменение
задачи во время генерации приводит к 409 `task_changed`, а не к потере новых правок.
Подтверждённые и опубликованные снимки AI не изменяет. Исходный текст сохраняется.

`python -m pytest -q` проверяет оба режима через MockTransport без сети и оплаты,
включая негативные ответы и миграцию SQLite. Живой прогон 23.09.2026 на синтетическом
магазине с `gpt-4o-mini`: обе операции вернули 200, получены 7 вопросов и рабочая
карточка; неизвестные поля пусты, подтверждение и публикация не выполнены.

Интеграция основана на официальной документации:
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[Responses API](https://developers.openai.com/api/reference/python/resources/responses/methods/create).
