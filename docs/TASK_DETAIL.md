# Каталог и страница опубликованной задачи

Интерфейс использует `GET /api/catalog` и `GET /api/catalog/{id}` из API v0.4
(`feat/backend-workflow`, `380d94a`). Backend нужно включить при общей
синхронизации: наша ветка сохраняет серверные файлы без изменений.

Каталог показывает только published_card, published_rating, опубликованную тему
и дату. Приватные черновики не запрашиваются, оценки не вычисляются клиентом.
Сортировка: рейтинг по убыванию, дата публикации и ID по возрастанию.
Поиск и фильтры работают по публичному списку; подписи тем переведены на русский.

Фильтры и позиция возврата сохраняются в sessionStorage. Каталог обновляется
при входе и кнопкой «Обновить». Пустой серверный список отличается от пустой
выборки фильтров. Ошибки не подменяются примерами.
catalog-demo.json сохранён как историческая тестовая фикстура и не загружается UI.

Маршрут `/ui#task/{encoded-id}` поддерживает прямые ссылки и перезагрузку.
Страница показывает контекст, потребность, пользователей, данные, ограничения,
результат, критерии, контакт и формат взаимодействия. Пустые сведения —
«Нужно уточнить», рекомендации ИИ отделены от требований бизнеса.
Оценка null — «Ещё не рассчитан»; рейтинг 0 не препятствует отклику.

Есть загрузка, отсутствующая публикация, ошибка и повтор. Устаревшие запросы
отменяются/игнорируются при навигации. Текст выводится как текст, не HTML.

Порядок: team-api.js → proposal-form.js → task-detail.js → shell.js,
затем catalog.js, builder.js, team-workspace.js. Секция #page-task создаётся
до обработки прямого маршрута оболочкой.
