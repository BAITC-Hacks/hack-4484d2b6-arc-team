# Участник №3 — шаг 2: полная страница задачи

Страница объединена с API v0.3 (шаги 1–3 участника №1) и конструктором бизнеса
(шаги 1–2 участника №2). Форма отклика — следующий шаг, здесь её нет.

## Просмотр

После запуска FastAPI открыть `/ui#catalog` и любую карточку. Вместо диалога
открывается `/ui#task/preview-delivery` (ID зависит от выбранного примера).
Прямая ссылка работает и после обновления страницы.

Страница содержит контекст, потребность, пользователей, данные, ограничения/сроки,
ожидаемый результат, критерии успеха, контакт и формат взаимодействия. Пустое поле
показывает «Нужно уточнить». Рекомендации ИИ отделены от требований бизнеса.
Оценка null отображается как «Ещё не рассчитан», без нулевого прогресса.

«Назад в каталог» и браузерная кнопка назад сохраняют выбранную тему, готовность
и текст поиска. В пределах той же вкладки фильтры переживают перезагрузку благодаря
sessionStorage; при запрете хранилища навигация без перезагрузки продолжает работать.
При обычном переходе из карточки сохраняется также позиция каталога.

## Источник данных и ограничения

Публичный `/api/catalog/{id}` ещё не реализован в проверенной main. Используется
только `/static/catalog-demo.json`, явно помеченный как демонстрационный набор.
Описание и контакты синтетические; баллы — примеры для интерфейса, не результат
серверной формулы. Набор расширен до всех полей TaskCard. Эти записи не создаются
в БД и не считаются реальными публикациями или сгенерированными AI-ответами.

Для следующей интеграции заменить `loadTask()` в `task-detail.js` публичным GET,
согласовав response shape с участником №1. Использовать только published_card и
published_rating. Не читать приватный `/api/tasks`, proposed_card или confirmed_card.
Не подменять неуспешный реальный запрос синтетической карточкой незаметно.

Есть загрузка, отдельное состояние отсутствующей задачи, ошибка данных/сети и
повтор. Ожидание ограничено 12 секундами; предыдущий запрос отменяется при смене
страницы, запоздавший ответ не подменяет текущую задачу. Текст выводится через
textContent, а не как HTML. Контакты отображаются текстом без внешних запросов.

## Границы файлов для параллельной работы

- Новые `app/static/task-detail.js` и `task-detail.css` принадлежат участнику №3.
- JS сам добавляет секцию `#page-task` в `#main-content`.
- В `base.html` добавлены подключения CSS/JS; удалён прежний диалог каталога.
  Разметка `#page-builder`, демопрофили, общие стили и сервер не изменены.
- **Порядок:** `task-detail.js` загружается с defer до `shell.js`, чтобы секция
  существовала при обработке прямой ссылки. `catalog.js` загружается после shell.
- В `shell.js` добавлен маршрут `#task/<encoded-id>`; активным пунктом остаётся
  каталог. Сохранить это при слиянии с изменениями участника №2.
- `catalog.js` теперь создаёт ссылки вместо кнопок диалога и хранит фильтры.
- Общий README отражает оба готовых шага интерфейса команды.

## Ручная проверка

1. Выбрать «Образование» и «Черновик», открыть задачу с 35 баллами: она доступна.
2. Убедиться, что неизвестные данные/сроки/критерии помечены, рекомендации отдельно.
3. Вернуться: фильтры и прежняя выборка остаются. Повторить после обновления страницы.
4. Открыть прямую ссылку на доставку: все разделы отображаются, рейтинг 90/100.
5. Открыть `#task/missing`: «Задача не найдена», есть возврат в каталог.
6. При недоступности JSON: ошибка с повтором, а не чужая задача или вечная загрузка.
7. Быстро перейти между задачей и каталогом: старый ответ не меняет текущую страницу.

Автотесты: `python -m pytest -q`. JS-синтаксис: `node --check app/static/task-detail.js`.
