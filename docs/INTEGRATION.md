## Проверено

- Серверные тесты хранения, миграций, AI, рейтинга и публикации.
- Совместный путь: создание → вопросы → ответы → генерация → ручная правка →
  подтверждение → публикация → последующая правка и генерация → перезапуск.
  Опубликованный снимок сохраняется до явного повторного подтверждения и публикации.
- В браузере: локальная генерация вопросов и карточки, пустое поле после ответа
  «не знаю», сохранение после перезагрузки, разделение черновиков двух бизнесов,
  восстановление несохранённой правки после смены бизнеса.
- Отсутствующий ключ OpenAI: видимая ошибка, явный локальный повтор, сохранение
  карточки. Отмена повторной генерации сохраняет ручные правки.
- Роль команды скрывает конструктор. Каталог фильтрует карточки, включая низкий
  рейтинг; полная страница показывает неизвестные поля и отдельные рекомендации.

Для браузерного прогона использована отдельная синтетическая БД; рабочие данные
пользователя не очищались. Оплачиваемые запросы не выполнялись.

контракт с опубликованными снимками, включая `published_topic`.

## Продолжение работы

После синхронизации main сохранить или закоммитить свои локальные правки, затем
выполнить `git fetch origin` и `git merge origin/main` в своей рабочей ветке.
Для чистой локальной main: `git switch main` и `git pull --ff-only origin main`.
Не использовать принудительный push и не заменять чужие изменения целыми файлами.

После обновления перезапустить FastAPI. Повторный `seed.py` безопасно добавляет
отсутствующие демозаписи, существующие записи не затирает. Тесты: `python -m pytest -q`.
Для работы с рейтингом использовать контракт [API.md](API.md) и [SCORING.md](SCORING.md).
