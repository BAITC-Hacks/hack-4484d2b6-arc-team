# Участник №2 — шаг 4: кабинет бизнеса

Кабинет из `feat/business-ui` объединён с API v0.4 и интерфейсом команды.
Полный пользовательский сценарий проверен через обе роли; отдельное подключение
backend больше не требуется. Итоговый отчёт: [INTEGRATION.md](INTEGRATION.md).

## Возможности

Открыть `/ui#business` после обычного запуска FastAPI и `seed.py`.

- Задачи выбранного бизнеса: публикация, подтверждённый серверный рейтинг, неподтверждённые/неопубликованные изменения, фильтр, счётчики, состояния загрузки, пустого списка и ошибки.
- Переход к конкретной задаче или новой задаче в существующем конструкторе. Несохранённые правки сохраняются; бизнес синхронизируется между страницами.
- Все предложения выбранной задачи: команда, идея, план, срок, ссылка на прототип и вопросы. Отсутствие прототипа явно подписано. Сравнение отмеченных предложений в таблице без рейтинга участников и без лимита выбранных команд.
- Ручные «Выбрать команду» и «Отклонить» только для `submitted`. Контракт сервера считает решение окончательным; UI не предлагает его менять. Выбор одной команды не принимает решений за остальные.
- Результаты этапов из `proposal.milestones`: описание, ссылка, статус, подтверждение бизнесом. Отображаются точные `points_awarded` сервера, без клиентской формулы. Повторное подтверждение недоступно после успеха. Баллы команды не меняют рейтинг задачи.
- Ошибка операции сохраняет прежний отображаемый статус и предлагает обновить данные. Успех показывается только после валидного ответа сервера. Во время записи блокируются повторные клики и переключение владельца; автоматического повтора записи нет.

Все пользовательские строки выводятся как текст. Ссылки допускают только абсолютные HTTP/HTTPS и открываются с `noopener noreferrer`. Кабинет скрывается для роли команды; это демонстрационный выбор профиля, не production-авторизация. Владение проверяет сервер.

## Контракт подключения

`app/static/business-api.js` — адаптер к опубликованному контракту backend-workflow. Каждый запрос владельца передаёт `X-Demo-Business-Id`.

| Операция | Запрос / ответ |
|---|---|
| GET `/api/demo/profiles` | Бизнесы и команды |
| GET `/api/tasks` | Задачи владельца |
| GET `/api/tasks/{task_id}/proposals` | `ProposalView[]`, включая `team_name`, `task_title`, `milestones` |
| PATCH `/api/proposals/{proposal_id}` | `{"status":"selected"}` / `{"status":"rejected"}` → `ProposalView` |
| POST `/api/milestones/{milestone_id}/confirm` | Без тела → `Milestone` |

Отдельного GET этапов нет: они уже вложены в предложения. Кнопка «Обновить» получает актуальные предложения с этапами. Шкала MVP — 10 баллов, задана сервером; UI её не дублирует.

Доступность операций проверяется через `/openapi.json`. На API 0.3 показано «Отклики ещё не подключены», вместо фиктивного пустого списка или успеха. Ошибка загрузки OpenAPI показывается как ошибка. Если требуются неизвестные обязательные поля записи, действие остаётся недоступным. Такая проверка не заменяет серверную авторизацию.

## Проверка

```sh
# В отдельном терминале:
chromedriver --port=9515
# Кабинет бизнеса:
.venv/bin/python tests/browser_business.py
# Регрессия конструктора, рейтинга и публикации:
.venv/bin/python tests/browser_builder.py
# Обычные серверные проверки:
.venv/bin/python -m pytest -q
```

`browser_business.py` автоматически различает версии API. На 0.3 сначала проверяет настоящие задачи, сохранность правок и изоляцию профилей, затем явно подключает **тестовые** маршруты из `business_api_fixture.py` к своему экземпляру приложения. Фикстура проверяет небезопасный текст/ссылки, ошибки, неверный ответ, неизвестные обязательные поля, двойной клик, сравнение и несколько выбранных команд. Значения 7 и 13 баллов в ней специально проверяют отображение серверных значений; это не шкала продукта. Фикстура не импортируется приложением и не входит в seed.

При наличии API 0.4 тот же запуск выполняет `browser_business_workflow.py` с **настоящими** маршрутами. В браузере пройдено: новый черновик → вопросы → ответы → редактирование → подтверждение → публикация с 0 баллов → пять предложений → сравнение → выбор двух команд → отказ одной → подтверждение этапа → 10 баллов. Предложения и результат этапа отправляются через настоящий API команды, поскольку страницы команды принадлежат участнику №3. Проверены повторное подтверждение без повторных баллов, сохранность после перезагрузки, изоляция владельца и неизменность рейтинга задачи.

Оба режима используют временную SQLite и отдельный браузерный сеанс. Рабочая БД не меняется, внешняя модель не вызывается. Успешный локальный AI-прогон не является проверкой качества OpenAI.

## Общая интеграция

Backend, конструктор, кабинет бизнеса и страницы команды объединены. Текущие
файлы конструктора и рейтинга сохранены. Полный сценарий с отправкой откликов
и этапов через страницы команды пройден; итог — в [INTEGRATION.md](INTEGRATION.md).

Новые файлы UI: `business.js`, `business-api.js`, `business.css`. Общая оболочка дополнена разделом кабинета и диалогом сравнения; в `builder.js` добавлен небольшой интерфейс `SanaBuilder` для перехода с сохранением правок. Сервер и страницы команды в эту реализацию не копировались.
