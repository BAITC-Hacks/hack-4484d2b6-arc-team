# Участник №3 — шаг 3: форма и локальные черновики

Объём согласован: только интерфейс и черновики. Серверный API откликов реализует
участник №1. Форма не выполняет POST, не создаёт запись в SQLite и не показывает
фиктивного сообщения об успешной отправке. Кнопка отправки отключена.

## Пользовательский сценарий

1. Открыть `/ui#catalog`, выбрать задачу и нажать «Подготовить отклик».
2. Переключиться на роль команды и выбрать один из профилей `/api/demo/profiles`.
3. Заполнить идею, план и сроки. Ссылка на прототип и вопросы бизнесу необязательны.
4. Черновик автоматически сохраняется при вводе. «Сохранить черновик» сохраняет
   даже неполное предложение; «Проверить отклик» показывает ошибки около полей.
5. После смены команды, задачи или перезагрузки возвращается соответствующий
   черновик. Сведения одного отклика не переносятся в другой.

Низкий рейтинг задачи не закрывает форму. Пустые и пробельные обязательные поля
отмечаются при проверке. Ссылка должна быть абсолютной HTTP(S), без встроенного
логина и пароля; сервер её не открывает. Пустая ссылка означает отсутствие прототипа.
Все пять полей ограничены 20 000 символов согласно текущей модели Proposal.

## Хранение и границы

Ключ: `ai-sana:proposal-draft:v1:` + JSON-массив `[source, task_id, team_id]`.
Значение: `{version: 1, source, task_id, team_id, values, updated_at}`.
`values` содержит `idea`, `plan`, `timeline`, `prototype_url`, `questions`.
Выбор команды хранится в `ai-sana:proposal-team`. Сейчас `source` всегда `demo`.

Хранение — localStorage текущего браузера. При запрете или переполнении хранилища
форма сохраняет ввод в памяти вкладки и показывает предупреждение; после закрытия
или перезагрузки такой ввод может потеряться. Не считайте черновик серверной записью.
При уходе отменяются незавершённые запросы профилей. Тексты выводятся как текст/значения
полей. Роль и профили остаются демонстрационными, без настоящей авторизации.

## Передача участнику №1 и следующая интеграция

- `app/static/proposal-form.js` и `proposal-form.css` изолированы от конструктора бизнеса.
- `task-detail.js` вызывает `window.SanaProposalForm.mount(host, {id, title, source})`.
  Скрипт формы должен быть подключён до скрипта страницы задачи.
- Пока каталог использует `preview-*`, не отправлять эти ID в API и не сопоставлять
  их с реальными задачами по названию. Сначала подключить публичные опубликованные задачи.
- Будущий POST из [API.md](API.md): `/api/tasks/{id}/proposals`, выбранная команда
  в `X-Demo-Team-Id`; поля — `idea`, `plan`, `timeline`, `prototype_url`, `questions`.
  Это планируемый контракт, не утверждение о готовом endpoint.
- Перед отправкой обрезать внешние пробелы, пустую ссылку передавать как `null`.
  Сервер должен проверить профиль, опубликованную задачу, длины и схему ссылки.
- Показывать успех только после ответа сервера, сохранять ввод при ошибках,
  блокировать повторную отправку и согласовать защиту от дублей с backend.

## Проверка

В браузере проверены: пустые обязательные поля, заполненное предложение без
прототипа, отклонение `javascript:` и принятие HTTPS, перезагрузка, смена двух команд,
открытие другой задачи, доступ на карточке с 35 баллами и отключённая отправка.
Проверено оформление на обычном настольном размере окна. Синтаксис:
`node --check app/static/proposal-form.js`. Общие тесты: `python -m pytest -q`.

Проверка реальной отправки не выполнялась: API намеренно отсутствует в этом шаге.
