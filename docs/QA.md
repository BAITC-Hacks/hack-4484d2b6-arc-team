# Шаг 5 участника №1 — проверка сервера

Проверена ветка `feat/backend-workflow`, API 0.4.0, на основе серверного шага 4
(`380d94a`). Результат: **116 тестов прошли**. В этом шаге добавлены проверки и
документация; производственный код, зависимости и схема БД не менялись.

## Требования и результат

| Требование | Что проверено | Где воспроизвести |
|---|---|---|
| Формула рейтинга | Семь весов из кейса, сумма 0–100, начисления по полям, пустые значения и заглушки | [test_scoring.py](../tests/test_scoring.py) |
| Границы уровней | 39/40, 69/70, 89/90 в функции; реальные карточки проходят подтверждение, публикацию и фильтр каталога с сохранением оценки | [test_scoring.py](../tests/test_scoring.py), [test_workflow.py](../tests/test_workflow.py) |
| Сохранение данных | Исходный текст, ответы, карточки, решения и этапы сохраняются при повторном создании приложения с той же SQLite; повторный seed их не стирает | [test_storage.py](../tests/test_storage.py), [test_integration.py](../tests/test_integration.py), [test_workflow.py](../tests/test_workflow.py) |
| Низкий рейтинг | Задачи с 0, 30 и 39 баллами публикуются, видны в каталоге и принимают отклики | [test_publication.py](../tests/test_publication.py), [test_workflow.py](../tests/test_workflow.py) |
| Несколько команд | Две команды выбираются для одной задачи; выбор не отклоняет остальных; обе могут передать результаты и получить свои баллы | [test_workflow.py](../tests/test_workflow.py) |
| Однократные баллы | Повторы отправки и подтверждения, включая четыре параллельных запроса, сохраняют один этап и одно начисление; разные этапы суммируются | [test_workflow.py](../tests/test_workflow.py) |

## Дополнительно проверено

- Полный серверный путь: исходное описание → локальный AI → карточка с 30 баллами →
  публикация → два отклика → выбор обеих команд → два результата → подтверждение.
  Между действиями приложение переоткрывается: подтверждённый этап сохраняет 10
  баллов, ещё не подтверждённый — 0. После его подтверждения у каждой команды 10;
  рейтинг задачи остаётся 30. SQLite `integrity_check` возвращает `ok`, нарушений
  внешних ключей нет.
- Два одновременных противоположных решения бизнеса дают ровно один успех и один
  конфликт 409. Сохранённый статус соответствует победившему запросу; предложение
  другой команды остаётся `submitted`.
- Через API подтверждены и опубликованы карточки с баллами 0, 39, 40, 69, 70, 86,
  90 и 100; публичные ответы и фильтры согласованы с подтверждённым рейтингом.
  В текущей формуле 89 недостижим: ближайшая достижимая оценка ниже 90 — 86.
  Граница 89/90 отдельно проверяется для функции определения уровня. Дополнительно
  проверены все 512 комбинаций заполнения девяти оцениваемых полей.
- Чужой демопрофиль не читает отклики и не принимает решения; невыбранная команда
  не отправляет этап. Произвольные статусы, баллы и недопустимые ссылки отклоняются.
- Каталог не выдаёт исходный текст и рабочие правки. Изменение опубликованной задачи
  не меняет её публичную карточку до нового подтверждения и публикации.
- В отслеживаемых Git-файлах не найдены шаблоны ключей OpenAI; `.env` исключён из
  Git и не отслеживается. В ходе проверок внешние AI-запросы не выполнялись.

## Повтор проверки

Из корня репозитория после установки `requirements-dev.txt`:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Linux/macOS: `.venv/bin/python -m pytest -q`.

Новые проверки добавлены в существующий `tests/test_workflow.py`. Для отдельного
прогона: `python -m pytest tests/test_workflow.py -q`.
Тесты создают временные БД и не очищают рабочую базу. Внешний AI имитируется либо
используется явно выбранный `local`; ключ и оплата не требуются.

Набор завершился с одним предупреждением Starlette о будущем переходе TestClient
с `httpx` на `httpx2`; ошибок и упавших тестов нет. Зависимости ради предупреждения
не менялись.
