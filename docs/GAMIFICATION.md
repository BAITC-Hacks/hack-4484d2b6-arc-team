# Геймификация и таблица лидеров

Геймификация включена в общую сборку вместе с сервером и кабинетами бизнеса и команды. Новых зависимостей, таблиц или миграций нет. Отчёт об объединении — [INTEGRATION.md](INTEGRATION.md).

## Бизнес: семь шагов

Конструктор использует категории `confirmed_rating` из серверного ответа. Шаг выполнен, если все его поля дают максимальные баллы. Подсказка выбирает незаполненное поле с наибольшим весом и переводит фокус в редактор. Вес берётся из ответа сервера; клиент не пересчитывает рейтинг по введённому тексту.

Правки не дают баллов до ручного подтверждения. После успешного подтверждения, повысившего уровень, появляется сообщение «Новый уровень». Публикация доступна при любом рейтинге. Прогресс означает полноту сведений, а не доказанное качество задачи.

## Команды: достижения

| Достижение | Условие |
|---|---|
| Первый результат | Один подтверждённый бизнесом этап |
| Довели до результата | Три подтверждённых этапа, в том числе в одной задаче |
| Разный опыт | Подтверждённые этапы в задачах двух разных бизнесов |

Прогресс и достижения вычисляет сервер из подтверждённых этапов. За этап начисляется 10 баллов согласно существующим правилам. Повторное подтверждение не создаёт новую награду или новые баллы. Достижения не дают дополнительных баллов.

## Таблица лидеров

Страница `/ui#leaderboard`, публичный `GET /api/leaderboard`, без заголовка демопрофиля.

**Выполненная задача в этом рейтинге** — уникальная задача, по которой у команды есть хотя бы один подтверждённый этап. Это временное правило первого билда, а не свидетельство полного завершения проекта: отдельного статуса завершения проекта в модели нет.

- Несколько этапов одной задачи дают одну выполненную задачу.
- Несколько выбранных команд могут независимо получить результат по одной задаче.
- Неподтверждённые этапы, отправленные и отклонённые отклики не дают результата.
- Порядок: число задач по убыванию, затем ID команды для стабильного отображения.
- При равном числе задач место одинаковое: например, `1, 1, 3`. Баллы не влияют на место.
- Возвращаются все команды, включая команды без результатов. Начальная демобаза не содержит вымышленных достижений.

Ответ — массив объектов с полями `team_id`, `name`, `rank`, `completed_tasks`, `confirmed_milestones`, `businesses`, `points`, `achievements`. Каждое достижение содержит `id`, `title`, `description`, `progress`, `target`, `earned`; прогресс ограничен целью. Приватные тексты задач, ссылки на результаты и контакты не возвращаются. Пустая база даёт `[]`.

Интерфейс обновляется при входе в раздел и по кнопке «Обновить». При ошибке старые результаты скрываются, показывается возможность повторить загрузку. Реального времени, сезонов и пагинации нет; для большого количества команд потребуется пагинация. Демопрофили не обеспечивают защиту от намеренной накрутки пользователем, переключающим роли.

## Проверка

1. Запустить приложение по README. Открыть «Лидеры команд»: у пяти демокоманд по нулю результатов, достижения пока не получены.
2. В конструкторе подтвердить карточку с одним названием: 0 баллов, 0 из 7 шагов. Нажать «Уточнить поле» — фокус переходит к данным.
3. Заполнить данные, контекст и потребность. До подтверждения рейтинг прежний. Подтвердить: 40 баллов, 2 из 7 шагов, сообщение о новом уровне.
4. Через конструктор, каталог и кабинеты выполнить публикацию, отклик, ручной выбор команды, отправку и подтверждение этапа. Альтернативный путь — Swagger: [контракт API](API.md).
5. Обновить таблицу: одна задача, один этап, 10 баллов, «Первый результат» получен.
6. Подтвердить этот этап повторно: показатели прежние. Подтвердить второй этап той же задачи: одна задача, два этапа, 20 баллов.
7. Подтвердить третий этап в задаче другого бизнеса: две задачи, три этапа, 30 баллов, все три достижения получены.

Проверено: `python -m pytest -q` — **119 passed**. Новые API-тесты проверяют пустую базу, нулевые результаты, разные команды, равные места, повторное подтверждение, несколько этапов одной задачи, разные бизнесы и сохранность после перезапуска. В браузере вручную проверены нулевой и заполненный рейтинг, достижения, переход к полю, сохранение прежнего балла при вводе и повышение уровня после подтверждения. Использовалась отдельная тестовая SQLite-база, без OpenAI-запросов.
