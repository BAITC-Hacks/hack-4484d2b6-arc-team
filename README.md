# AI Sana Challenge Hub

ARC Team · HackAlem AI · от бизнес-задачи к решению.

## Текущий результат: объединённые шаги команды

| Участник | Готово в общей версии | Следующий шаг, ещё не реализован |
|---|---|---|
| №1 — backend | Шаги 1–3: хранение, AI-конструктор, подтверждение, рейтинг, публикация | Шаг 4: публичный каталог, отклики и результаты |
| №2 — интерфейс бизнеса | Шаги 1–2: Soft Retro и работающий конструктор | Шаг 3: панель рейтинга, подтверждение и публикация из интерфейса |
| №3 — интерфейс команды | Шаги 1–2: каталог примеров и полная страница задачи | Шаг 3: форма отклика |

Первый шаг участника №2: Soft Retro по согласованному макету. Реализованы общие цвета, кнопки, карточки, статусы, боковая навигация, переключение демонстрационной роли и адаптация оболочки под размер окна. Все ресурсы интерфейса локальные, внешних библиотек и шрифтов в браузере нет.

Второй шаг участника №2 подключает конструктор к API: описание → уточняющие вопросы → редактируемая карточка. Работают сохранение на сервере, повторное открытие черновиков, выбор реального демонстрационного бизнеса и восстановление локальных правок при ошибках. Источник вопросов и карточки явно подписан; переход к локальному режиму после ошибки OpenAI требует нажатия пользователя.

**Подтверждение, рейтинг и публикация работают через API и `/docs`.** Их кнопки и панель рейтинга в конструкторе пока не подключены — это шаг 3 участника №2. Кабинеты обозначены как будущие страницы. Каталог и полная страница участника №3 показывают пять явно обозначенных демонстрационных карточек, независимо от опубликованных записей БД.

## Просмотр

Из корня репозитория (Linux/macOS, Python 3.12+):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python seed.py
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/ui. По умолчанию используется явно обозначенный локальный режим; ключ не нужен. Повторный seed не затирает существующие записи. Конструктору нужен FastAPI: статический `http.server` позволяет увидеть оформление, но не выполнять API-операции.

Windows PowerShell (Python 3.12+):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -X utf8 seed.py
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

После обновления репозитория перезапустите сервер: миграции БД выполняются автоматически. Не удаляйте существующую базу. Конфигурация OpenAI описана в [docs/AI.md](docs/AI.md); ключ хранится только в локальном `.env`, который исключён из Git.

При запуске FastAPI по [инструкции сервера](docs/BACKEND.md) интерфейс доступен на
http://127.0.0.1:8000/ui, каталог — http://127.0.0.1:8000/ui#catalog.

Проверка: выбрать бизнес, описать задачу, нажать «Получить вопросы», ответить и нажать «Сформировать карточку». Исправить название, сохранить правки и обновить страницу: карточка должна восстановиться. Неизвестное можно оставить пустым или ответить «не знаю». Можно выбрать другой сохранённый черновик или создать новый. Выбор роли и несохранённые правки сохраняются локально, если браузер разрешает хранилище. Профили синтетические; переключатель не выполняет авторизацию.

## Передача другим участникам

- `app/templates/base.html` — общая HTML-оболочка с действующим конструктором и каталогом примеров; FastAPI отдаёт её на `/ui`. Шаблон не требует Jinja.
- `app/static/styles.css` — общие CSS-переменные и компоненты: `.button`, `.button-primary`, `.button-outline`, `.panel`, `.badge`, `.icon`, `.form-field`, `.field-control`, `.field-error`. Стили других страниц добавлять отдельными файлами. Палитра: молочный `#F8F5ED`, тёмно-синий `#172B4D`, голубой `#DCEAFF`, мятный `#DDF3E5`, жёлтый `#F9E6A4`, основная кнопка `#216BE0`.
- `app/static/icons.svg` — локальный SVG-спрайт; `favicon.svg` — знак приложения. Внешних шрифтов, библиотек и заимствований из JARVIS нет.
- `app/static/shell.js` — навигация и демороль: `#builder`, `#catalog`, `#task/<id>`, `#business`, `#proposals`. Последние два кабинета пока являются заглушками.
- `app/static/builder.js`, `builder.css` — конструктор бизнеса и его стили, совместимые с API v0.3; подробности — [docs/BUSINESS_UI.md](docs/BUSINESS_UI.md).
- `app/static/task-detail.js`, `task-detail.css` — полная страница задачи. Скрипт создаёт секцию до запуска `shell.js`; сохраняйте этот порядок при правке общей оболочки. Подробности — [docs/TASK_DETAIL.md](docs/TASK_DETAIL.md).

Сервер раздаёт `app/static` по `/static` и оболочку на `/ui`; API на `/` сохранён. Контракт сервера и идентификаторы профилей описаны в docs/API.md. Переключатель роли выставляет `data-demo-role` на `<html>` и отправляет событие `sana:demo-role-change` с `detail.role` (`business` или `team`). В роли команды конструктор скрыт. Бизнес выбирается отдельно из `/api/demo/profiles`; запросы конструктора передают его ID в `X-Demo-Business-Id`. Проверка принадлежности задач остаётся на сервере.

## Участник №3 — шаги 1–2: каталог и полная страница

Реализованы карточки в стиле Soft Retro, поиск по названию/описанию/результату,
совместные фильтры по теме и готовности, сортировка по баллу (при равенстве — по
времени и ID), сброс, пустое состояние, ошибка загрузки с повтором и полная страница задачи.
Карточка с 35 баллами доступна так же, как остальные.

`app/static/catalog-demo.json` — синтетические **примеры отображения**, а не
опубликованные записи БД. Баллы заданы только для демонстрации уровней и не доказывают
работу серверной формулы. Клиент не считает рейтинг и не читает приватный `/api/tasks`.
Полная страница показывает все поля карточки, отмечает неизвестное и отделяет рекомендации
от требований бизнеса. Прямые ссылки, возврат и сохранение фильтров работают после перезагрузки.
Отклики остаются следующим шагом.

Стили изолированы в `catalog.css`, поведение — в `catalog.js`. После появления
публичного API заменить источник в `load()` и сверить согласованный формат:
`id`, `topic`, `status`, `published_at`, `published_card`, `published_rating`.
Не переключаться на фиктивные данные незаметно при ошибке реального API.

Проверка: открыть каталог, выбрать «Черновик · 0–39», открыть задачу с 35 баллами,
вернуться в каталог, выбрать дополнительно «Логистика» (пустой результат), сбросить
фильтры и найти «диспетчеру». Должна остаться одна задача. Без фильтров баллы идут
90, 75, 75, 55, 35. Общие тесты: `python -m pytest -q`.

Следующие шаги участника №2: подключить подтверждение, публикацию и серверную панель рейтинга после backend-шага 3, затем кабинет бизнеса. Общий план проекта: [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md). Выбранный Soft Retro заменяет прежнее упоминание тёмной темы в историческом плане.

## Backend — шаги 1–3

Работают FastAPI + SQLite, демонстрационные профили, сохранение черновиков,
уточняющие вопросы и генерация карточки через OpenAI либо явно обозначенный local-режим.
На шаге 3 добавлены подтверждение карточки, рейтинг по семи категориям и публикация
подтверждённого снимка без минимального балла. Изменения `feat/backend-scoring`
объединены с конструктором и интерфейсом команды.

Публичный API каталога, отклики, выбор команд и подтверждение этапов — шаг 4.
Конструктор сохраняет данные в БД; только каталог и полная страница используют
статические примеры. Новые операции доступны через API и `/docs`, подключение к ним
выполнят участники №2 и №3.

## Проверка общей версии

`python -m pytest -q` проверяет хранение, миграции, AI-контракты и ошибки,
формулу, подтверждение/публикацию, ресурсы интерфейса и полный серверный путь от
черновика до публикации с последующим редактированием и перезапуском.

[Отчёт интеграции и границы проверки](docs/INTEGRATION.md).
Тесты не расходуют API-кредиты. Реальный вызов OpenAI в этой интеграции не выполнялся;
браузер проверен в явно обозначенном локальном режиме.
